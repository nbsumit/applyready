# Site audit, 6 November 2026: AdSense readiness and launch readiness

Scope: every page (57 HTML files), every tool, every external link, and every factual claim on the exam pages and guides, checked against the official documents on 6 November 2026. Google's current AdSense policies were read from support.google.com on the same day. This file records what was checked, what was found, what was changed, and what only the site owner can do.

## 1. Tools: all six work; three defects fixed

Each tool was driven in Chromium with the sample images in `img/samples/`, and every download was checked with Poppler, ImageMagick and Pillow, independently of the site's own tests.

| Tool | What was run | Result read back from the file |
|---|---|---|
| Image resizer | ID/passport preset on the 1200 × 1600 px portrait | JPEG 350 × 450 px, 27,109 bytes, under 50 KB |
| Image resizer | UPSC photo preset from the exam page, with a Devanagari name and date strip | JPEG 350 × 450 px, 29,894 bytes, within 20–200 KB |
| Image resizer | SSC signature preset on the signature photo | JPEG 709 × 236 px, 19,052 bytes, within 10–20 KB |
| Image resizer | PNG at 200 × 300 px with a 40 KB limit | Refused with "PNG needs 113.6 KB at this size" instead of exceeding the limit |
| Image to PDF | Portrait and signature photos, A4, auto orientation | 2 pages, 841.89 × 595.28 pt and 595.28 × 841.89 pt (A4), PDF 1.4 |
| Compress PDF | That PDF at a 150 KB target | 139.2 KB, 2 pages |
| Passport photo print | 35 × 45 mm on 4 × 6 in | JPEG 1200 × 1800 px; PDF 288 × 432 pt (4 × 6 in) with the image at 300 ppi |
| Signature cleaner | Default, then transparent PNG | JPEG 1600 × 900; PNG RGBA with 1,407,560 transparent pixels |
| Resume builder | Sample data, all exports | PDF (A4, title and author set, text extractable), DOCX (valid zip, Word XML), TXT, JSON backup |

Defects found and fixed:

1. **Compress PDF changed the page size.** Each rebuilt page took the embedded image's pixel size at 96 DPI, so an A4 page came back as 1200 × 675 pt and lost its margins and orientation. `js/compress-pdf.js` now reads the `/MediaBox` of each page and, when there is one image per page, keeps that size and fits the image centred on it.
2. **Compress PDF skipped camera JPEGs.** It cut each JPEG at the first `FF D9` marker, which in a camera JPEG is the end of the EXIF thumbnail, so the page decoded as nothing and was dropped. The JPEG is now walked segment by segment to the start of scan before the end marker is looked for. A UI test builds such a PDF and checks the output.
3. **Passport sheet JPEG had no print resolution.** The JFIF header now records 300 DPI, so a photo lab reads a 1200 × 1800 px sheet as 4 × 6 in.

Not changed, by design: a text-only PDF is refused with a message that says the tool is for scanned or image PDFs.

## 2. Pages: crawl and links

- All 57 pages loaded at 1280 px and 390 px with no console errors, no failed requests, no horizontal overflow, one `h1` each, a description and a canonical on every indexable page, alt text on every image, and no visible ad placeholder.
- Every internal link and anchor resolves (0 problems across all pages).
- All 56 external URLs were probed. All return 200 except hosts that block requests from outside India (ibps.in, neet.nta.nic.in, RRB sites); the research agents reached ibps.in and the NTA bulletin by other means and confirmed the content. `www.rrbranchi.gov.in` had an expired TLS certificate, so the link was removed and the fact annotated. `www.ncs.gov.in` redirected to `ncs.gov.in`; the links now point there.
- The unit (438), regression (48), content (6,007), browser (2,947), image workflow, resume flow, UI (2,875) and smoke suites all pass.

## 3. Facts: no wrong figure found; citations tightened

Every figure on the SSC, UPSC, IBPS, NEET and RRB pages, the Aadhaar/PAN/passport guide, the signature guide, the formats and DPI guides, and the nine resume guides was checked against the cited document. No numeric claim was wrong. Corrections made are listed in the editorial policy's corrections log for 6 November 2026. The unverifiable items remain as before: no RRB CEN and no UPSC NDA/CDS/CMS/IFoS notice could be opened from outside India; the pages say so.

One table on the Compress PDF page ("Official Document PDF Size Limits in India") gave figures for UPSC, SSC, state PSCs and universities with no source, and the UPSC row was wrong (the photo ID is a JPG of 20–200 KB, certificates are PDFs of 50–300 KB). It was replaced with the limits printed in the UPSC, NEET, IBPS and SSC documents, each cited.

| Navigation, about, contact, 404, HTTPS, robots | Pass | |

Decision left to the owner: the `adsbygoogle.js` loader is not on any page until a unit exists (`js/ads.js` adds it then). Google accepts the meta tag for verification, but its "site not ready" troubleshooting starts with "your ad code is missing", and it says reviews take longer "when the code isn't on a page that gets regular views". If the review stalls, verify the site in Search Console, or add the plain loader to the head of the content pages.

## 5. Launch steps only the owner can do

1. Merge and deploy. The service worker cache is now `applyready-v26` and the asset version `20261106`, so returning visitors get the new files.
2. In Google Search Console, verify `applyready.in` and submit `https://applyready.in/sitemap.xml`.
3. In AdSense, after approval: create one display unit, run `node scripts/enable-ads.js --slot <id>`, keep Auto ads off, publish the European regulations message in Privacy & messaging, then open a few pages with `?adpreview=1` and check the console for CSP reports.
4. Open an RRB CEN from an Indian network and add its photo and signature figures to the RRB page with the CEN number, paragraph and date (see `docs/content-quality/research/rrb.md`).
5. The contact form opens the visitor's email client (`mailto:`). It works without a server, but visitors with no mail client set up will see nothing happen; the page also prints the address, which is enough for launch.
